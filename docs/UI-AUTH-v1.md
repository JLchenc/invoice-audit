## 1. 现有 UI 评审结论

### 1.1 总体判断

现有前端是**质量过硬的 B 端作业系统界面**：设计 Token 体系完整（人机双色、差异优先、深色模式）、组件纪律好（卡片无阴影靠 0.5px 边框分层、等宽字体硬约束、Windows 雅黑加粗与整像素行高两个坑都已在规范里固化）。截图走查（亮 / 暗 / 1080 / 1280 / 1440）未发现视觉回退。**本版不改动任何既有页面视觉，只补认证体系这一块缺口。**

### 1.2 问题清单（按严重度）

| # | 级别 | 问题 | 证据 | 本版处理 |
|---|---|---|---|---|
| P0-1 | 阻断 | **无登录页、无路由守卫**。后端 `auth_enabled` 长期为 `False`（config.py 注释自述"前端还没有登陆页，先关"），`/api/*` 实际裸奔 | `server/app/core/config.py:25` | 补 `/login`、`/register`、`RequireAuth` 守卫 |
| P0-2 | 阻断 | **Header 用户区是硬编码 `AP` 头像**——那是 AI 员工工号，不是用户身份；登出无处可点 | `BasicLayout.tsx:320` | 改真实用户头像 + 下拉菜单 + 退出登录二次确认 |
| P0-3 | 高 | **401 只清 token 不跳转**：token 过期后用户面对一堆失败请求和空页面，没有任何"请重新登录"的引导 | `api/index.ts:123-127` | 401 → 清凭据 → 带来源路径跳 `/login` |
| P1-1 | 高 | **PRD 三角色（复核员 / 规则管理员 / 财务经理）无账号载体**：DB 无 users 表、无注册接口，权限只靠演示开关 | `models/*.py`、PRD §3 | 注册页按三角色设计；后端契约见 §5.2 |
| P1-2 | 中 | **"记住我"无存储策略区分**：token 只写 localStorage，浏览器重启后仍保持登录，与 12h 过期叠加出现"该过期不过期"的困惑 | `api/index.ts:52-58` | 记住我 → localStorage；否则 sessionStorage |
| P2-1 | 低 | `dist/`、`shot-*.png`、`scripts/tmp-*.mjs` 等走查产物散在 `web/` 根目录 | 目录走查 | 已在 `.gitignore` 覆盖，无需处理，仅记录 |

### 1.3 明确不动的东西（避免过度设计）

- 不改 Sider / Header / 工作台任何既有样式与交互；
- 不为"注册"造用户中心 / 找回密码 / 权限矩阵——PRD 未定义，页面只留入口位（禁用态 + tooltip）；
- 不引入第二套表单组件，全部复用 antd v6 + 现有 Token。

## 2. 认证信息架构

### 2.1 路由与守卫

```
/login      公开   已登录访问 → 重定向到来源页（无来源则 /review）
/register   公开   同上
/*          守卫   RequireAuth：无 token → /login?from=<当前路径>
```

守卫判断依据：`AuthProvider.user`（来自 `ia_token` + `ia_user` 缓存）。
token 过期（401）时由 `api/index.ts` 统一清凭据并跳 `/login`，形成闭环。

### 2.2 登录态状态机

```
匿名 ──登录成功──▶ 已登录 ──12h token 过期 / 主动退出──▶ 匿名
 ▲                  │
 └──401 统一拦截────┘   （任意 /api 返回 401：清 ia_token + ia_user → 跳 /login）
```

### 2.3 退出登录语义

JWT 无状态，**登出 = 客户端清凭据**，不调后端（服务端 12h 自然过期）。
防误触：Header 头像下拉 → 「退出登录」→ 二次确认 Modal → 清 `localStorage/sessionStorage` 两处 → toast → 跳 `/login`。

## 3. 页面设计

### 3.1 认证壳 AuthLayout（登录 / 注册共用）

```
┌────────────────────────────────────────────────────────┐
│                                                                │
│   ┌──────────────────────┐  ┌────────────────────────┐  │
│   │ 品牌 Panel（≥1024）   │  │  表单卡（居中）        │  │
│   │ 主色渐变 + 网格纹理   │  │  ┌──────────────────┐  │  │
│   │                      │  │  │ 标题 / 副标题      │  │  │
│   │ 发票智审              │  │  │ 表单字段…         │  │  │
│   │ 应付核算数字员工 AP-001│  │  │ 主按钮（block）   │  │  │
│   │                      │  │  │ 行内错误 Alert     │  │  │
│   │ · 人机边界           │  │  │ 底部链接          │  │  │
│   │ · 全程可审计         │  │  └──────────────────┘  │  │
│   │ · 键盘优先           │  │                        │  │
│   │                      │  │  演示账号提示（muted） │  │
│   │ 底部：© 2026         │  │                        │  │
│   └──────────────────────┘  └────────────────────────┘  │
│                      <1024：单列，品牌区压缩为顶部条        │
└────────────────────────────────────────────────────────┘
```

**设计决策**

1. **左品牌 Panel 用纯主色系渐变**（`#1E45B8 → #2A5CE0 → #4C7DF0`），**不掺 AI 青色**——v2 §2.1"人机双色永不混用"是硬约束，品牌渐变混色会让整套语义失效。深色模式换深海军蓝渐变（`#10131A → #1B2A52`），网格纹理换 `rgba(123,161,255,.08)`。
2. **表单卡 12px 圆角 + 1px 边框、无阴影**（§2.5：弹层级圆角；卡片不用阴影）。底色 `--ia-container`，明暗自动切换。
3. Panel 文案只讲三条产品原则（人机边界 / 可审计 / 键盘优先），全部来自 v2 §1，不新造卖点。
4. 输入框用 antd `size="large"`（40px）——登录是一次性低频操作，不继承工作台的 32px 紧凑控件，减少误输入。
5. 页面保留**主题切换按钮**：夜班场景（PRD US-9）进系统前就要能切深色。v1.1 起按钮收进表单卡右上角（与标题同行），不再悬浮卡外。

### 3.2 登录页 `/login`

| 区 | 规格 |
| --- | --- |
| 标题 | `登录` 20px/600 + 副标题 "登录以进入复核工作台" 13px 弱色 |
| 字段 | 用户名（`UserOutlined` 前缀）/ 密码（`LockOutlined` 前缀 + 眼睛切换显示） |
| 辅助行 | 「记住我」Checkbox（默认勾选，见 §1.2 P1-2）+ 「忘记密码」链接（禁用态 tooltip：请联系管理员重置） |
| 主按钮 | block、主色实心、loading 态防重复提交 |
| 错误态 | **行内 Alert**（§8：错误走行内 Alert 保留数据不丢）：服务端 401 → `ia-tag-diff` 语义红；字段错误 → 表单红字 + 输入框红框 |
| 演示提示 | muted 小字条：「演示账号 `admin` / `admin123`（后端 `auth_enabled=false` 时同样可登录）」——本项目是演示/作品向，降低体验门槛 |
| 底部 | 「还没有账号？**注册**」→ `/register` |
| 已登录 | 直接重定向来源页，表单不渲染 |

交互细节：回车提交（antd Form 原生）；提交期间按钮 loading + 字段禁用；登录成功 toast「欢迎回来，{用户名}」→ 跳来源页或 `/review`。

### 3.3 注册页 `/register`

| 字段 | 规则 |
| --- | --- |
| 用户名 | 4-20 位字母 / 数字 / 下划线，失焦校验，实时查重提示位（预留） |
| 邮箱 | 标准邮箱格式，前缀 `MailOutlined` |
| 密码 | ≥8 位，须含字母 + 数字；**4 段强度条**（弱红 / 中琥珀 / 强绿 / 极强深绿，§2.2 语义色复用） |
| 确认密码 | 与密码不一致实时红字 |
| 角色 | Select：复核员 / 规则管理员 / 财务经理（PRD §3），默认复核员 |
| 条款 | 必须勾选《使用条款与隐私政策》（链接位，暂 `#`） |

提交 → `POST /api/auth/register`（契约见 §5.2）：
- **成功** → toast + 跳 `/login` 并带入用户名（注册后登录，不自动登录，符合财务系统"审批感"）；
- **接口未实现（404/501）** → 行内 Alert：「注册服务暂未开放。当前为单管理员演示模式，请使用演示账号登录，或按 `docs/UI-AUTH-v1.md` §5.2 契约接入后端。」——**不假装成功**，这是可审计原则在注册流程上的体现。

### 3.4 退出登录（Header 用户菜单）

替换现硬编码 `AP` 头像：

```
┌────────────────────────┐
│ [头像] 用户名            │
│        复核员 · tag      │
├────────────────────────┤
│ 个人中心        （禁用） │
│ 退出登录        （danger）│
└────────────────────────┘
```

- 头像取用户名首字符，主色底白字（沿用现 `ia-logo-mark` 视觉，28px）；
- 「退出登录」→ themed `modal.confirm`（§8：静态方法拿不到主题，必须走 `App.useApp()`）：
  - 标题「退出登录？」；正文「退出后需重新登录才能访问工作台。未提交的驳回草稿将丢失。」
  - 取消（中性）/ 确认退出（danger）；
- 确认后清 `ia_token` + `ia_user`（local + session 两处）→ toast「已退出登录」→ `<Navigate to="/login" replace />`。

### 3.5 状态矩阵（§8 细则落地）

| 场景 | 规则 |
| --- | --- |
| 登录中 | 按钮 loading + 全表单禁用，防重复提交 |
| 密码错误 | 行内 Alert + 密码框清空聚焦 + 错误计数（≥5 次提示联系管理员） |
| 网络失败 | 行内 Alert「网络异常，请稍后重试」，保留已填内容 |
| 注册成功 | toast + 跳登录页 |
| 注册服务未开 | 行内 Alert 说明 + 演示账号引导 |
| token 过期 | 401 拦截 → 跳登录页，登录后回原页面 |
| 直接访问 /review | 守卫重定向 `/login`，登录后回到 `/review` |

### 3.6 无障碍（§9 基线）

- 所有输入 `<Form.Item name>` 自带 label 关联；图标前缀 `aria-hidden`，不单独传意；
- 错误除红外必须有文字（Alert 文案 + 字段级 message）；
- 全局 `:focus-visible` 2px 主色焦点环已覆盖；Tab 顺序 = 视觉顺序（品牌 Panel 无可交互元素，天然跳过）；
- `prefers-reduced-motion` 下关闭 Panel 入场动画；
- 对比度：品牌 Panel 白字压 `#2A5CE0` 5.67:1 ✅；表单正文 `#1F2329` on `#FFFFFF` ✅；弱色提示文字不低于 `--ia-text-3`（4.6:1）。

## 4. 设计决策备忘

1. **品牌 Panel 不混人机双色**：渐变只走主色系——把"蓝 = 人"的语义守住在认证入口，不给用户第一眼就混淆人机边界的机会。
2. **登录用 40px 控件而非 32px**：紧凑 Token 是为 6 小时作业设计的，登录是 10 秒一次性操作，防误输入优先。
3. **注册不自动登录**：财务系统注册后需"被感知"，跳登录页带入用户名，减少一步输入。
4. **登出纯客户端 + 二次确认**：JWT 无状态；确认弹窗防"手滑退出丢草稿"。
5. **401 闭环**：清凭据 → 带来源跳登录 → 登录后回原页，中途不丢工作现场。

## 5. 后端接口契约（前端已按此实现）

### 5.1 已有：`POST /api/auth/login`

请求 `{ "username": "admin", "password": "admin123" }`
响应 `{ "token": "<jwt>", "username": "admin" }`｜错误 `401 { detail: "用户名或密码错误" }`
> 已存在于 `server/app/api/biz.py:260`，前端直接对接。

### 5.2 待新增：`POST /api/auth/register`

```
请求  { "username": "zhangsan", "email": "zs@corp.com",
        "password": "******", "role": "reviewer" }
       role ∈ reviewer | rule_admin | finance_manager（PRD §3 三角色）
响应  201 { "username": "zhangsan", "role": "reviewer" }
错误  409 用户名已存在｜422 校验失败｜501 注册未开放
```

落地建议（最小集）：`users` 表（id / username / email / password_hash(bcrypt) / role / created_at）+ alembic 迁移 + 本端点；`role` 写入 token claims 后由 `get_current_user` 透传，为后续 RBAC 打底。**本期前端不阻塞**：404/501 时按 §3.3 降级提示。

### 5.3 登出

无接口。客户端清 `ia_token` / `ia_user`（localStorage + sessionStorage）。后续如需"踢下线"，用 Redis 维护 token 黑名单（服务端已有 Redis 连接，`app.state.redis`）。

## 7. v1.1 视觉强化修订（2026-10-25）

针对初评「太黑、太古板单调、主题按钮外露」的反馈，认证壳做了一轮视觉强化。产品身份是「AI 数字员工」，登录页是全产品唯一被允许放开做品牌氛围的地方：

| 修订 | 内容 | 理由 |
| --- | --- | --- |
| Agent 核心视觉 | 光球（「审」字徽记 + 光泽 + 呼吸缩放）+ 双轨环反向旋转 + 雷达扫描弧 + 8 颗漂浮粒子 | 把 L1–L6 全链路与「AI 在环视票据」变成可见的视觉隐喻，替代纯文字卖点 |
| 数据流光束 | 两条斜向慢移细光（青 / 蓝各一，12s / 16s） | 深空画布需要「数据在跑」的生气，静态渐变显得呆板 |
| AI 渐变标题 | 「会审票的 **AI** 员工」中 AI 二字用青色渐变 | 品名即身份，一眼认出这是 AI 员工而非普通工具 |
| 窄屏（<1024）不再裸奔 | 主背景升级为多层 mesh 光斑 + 网格纹理；卡片上方增加迷你 Hero（脉冲光球 + 品名 + 标语） | 左侧 Panel 在 <1024 整幅隐藏，原来右边是纯黑虚空 + 一张卡，是「太黑单调」的直接原因 |
| 主题按钮收进卡内 | 从页面右上悬浮条改为表单卡标题行右上角 | 悬浮条在框外显得多余且误触；卡内是登录页的常规位置 |
| 暗色 Panel 辉光增强 | 三层径向辉光（青 / 蓝 / 中蓝）+ 加深底色取代近黑 | #070b12 底 + 弱辉光在截图里读作纯黑虚空 |
| 玻璃 chips | 三条设计原则改为玻璃拟态小卡（5% 白底 + 模糊 + 细边） | 替换纯文字列表，与深空画布的材质统一 |

**边界声明**：以上氛围层（辉光 / 光束 / 扫描 / 粒子）只存在于认证壳。产品内（工作台等）继续保持 v2 的差异优先纪律：中性打底、彩色只给差异与 AI 语义虚线框，**不引入任何氛围装饰**。

**顺带修复的全站缺陷**：antd v6 消息条内容容器是全宽横条（1392×40）且 `pointer-events:auto`，任何 toast 都会吞掉屏幕顶部 3 秒内的点击——登录成功的提示曾盖住 Header 用户菜单吞掉第一次点击。已在 `global.css` 全局禁用消息条指针事件（cssinjs 运行时样式后置，需 `!important`）。

## 8. v1.2 背景图化 + v1.3 右锚定修订（2026-10-25）

| 可读性遮罩 | `.ia-auth-veil` 向卡片一侧压暗（径向 + 斜向线性渐变，移动端改纵向） | 背景永远只是氛围，不抢表单可读性 |
| 表单区右锚定（v1.3） | ≥1024 时 `.ia-auth-main` 改 `flex: 0 0 clamp(440px, 42vw, 560px); margin-left: auto`，右间隙收敛到 4-6% | 用户反馈「右侧空隙太大」——原 flex:1 均分导致 1440 下右空隙 17% |
| 渐变边框加粗（v1.3） | 卡片渐变边由 1px 加粗到 2px，透明度 0.42→0.55 | 用户反馈「渐变边框色可以粗一点」 |
| 中窄桌面适配 | 1024-1399 时光球 `left:50%` 且尺寸略收，避免压到品牌文案 | 右锚定后品牌列与光球的间隙在中窄桌面收紧 |

**窄屏（<1024）策略不变**：品牌列隐藏，迷你 Hero（徽标 + 品名 + 标语）+ 居中玻璃卡；光球移到顶部 10% 处作视觉锚点。移动端表单区保持 `flex:1` 全宽居中（右锚定仅 ≥1024 生效，避免 390px 下固定基准宽溢出视口）。
