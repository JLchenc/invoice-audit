## 0. 设计定位（先讲清楚"美观"在这类产品里是什么）

发票智审不是消费级产品，而是**财务共享中心的高频作业系统**。它的用户每天在同一块屏幕上待 6 小时、处理上百张单据。因此：

> **美观 = 可扫描（scannable）+ 确定性 + 低噪音 + 键盘优先。**
> 不是更大的圆角、更亮的渐变，而是让人一眼看到"哪里不一样"、手不用离开键盘、且**永远不会误判**。

**三类用户的权重排序**（来自 PRD §3）：

| 角色 | 使用频率 | 设计权重 | 核心诉求 |
| --- | --- | --- | --- |
| 复核员 | 极高（全天） | **70%** | 一屏看全、键盘完成、不误点 |
| 规则管理员 | 低（周级） | 20% | 改前知道影响、改后能回滚 |
| 财务经理 | 低（周级只读） | 10% | 一眼看懂趋势与成本 |

结论：**复核工作台是全系统的设计重心**，其余页面服务于它。

## 1. 四条设计原则

| 原则 | 含义 | 落到界面上 |
| --- | --- | --- |
| **① 差异优先** | 视觉重量全部服务于"哪里不一样" | 中性底色打底，只有差异 / 低置信 / 异常才允许出现彩色；一张单子里彩色区域就是"要看的地方" |
| **② 键盘优先** | 复核员 90% 操作不碰鼠标 | 决策条常驻置底 + J/K/A/S/E + ⌘K 命令面板 + 焦点环始终可见 |
| **③ 人机边界可见** | AI 只做建议，人做决定（PRD §6.3 原则一） | **人机双色系统**：蓝色 = 人的操作，青色虚线 = AI 产出。AI 区块永远虚线框、永远不出现"一键执行"按钮 |
| **④ 可审计** | 每个数字都能追到来源 | 字段值可溯源到影像坐标；每个判定可展开到规则版本与 trace |

## 2. 设计 Token

### 2.1 人机双色系统（本版核心决策）

| 语义 | 色值 | 用于 |
| --- | --- | --- |
| 主色（人） | `#2A5CE0`（hover `#4C7DF0`，active `#1E45B8`） | 主按钮、选中态、可交互元素、链接 |
| AI 色（机器） | `#0E7C9B`（浅底 `#E4F2F6`，深字 `#0A5C74`） | 抽取字段、置信度、AI 归因建议、LLM 成本 |

> **为什么值得做**：PRD 最硬的一条原则是"LLM 只做建议，规则和人做决定"。
> 用两套颜色固化它之后，不需要任何文案，用户看到青色虚线块就知道"这是机器说的、不能直接执行"。
> 面试时这是一句能讲三分钟的设计决策。

### 2.2 状态语义色（浅底 + 同系深字 + 0.5px 细边，圆角 4px）

| 语义 | 背景 | 边框 | 文字 | 场景 |
| --- | --- | --- | --- | --- |
| 通过 / 自动入账 | `#E8F6EE` | `#17934F` | `#0F6B3B` | 匹配无差异、容差内 |
| 差异 / 驳回 | `#FCEBEB` | `#D93A3A` | `#A32020` | 差异行、异常池、高危归因 |
| 留意 / 低置信 | `#FAEEDA` | `#C77700` | `#854F0B` | 置信度 < 0.9、提示级差异 |
| 停用 / 无意义 | `#F1EFE8` | `#B4B2A9` | `#5F5E5A` | 已归档、已作废 |

> 金融场景约定：**红 = 异常 / 高危，绿 = 通过**；本系统不涉及行情涨跌，不适用涨红跌绿。

### 2.3 中性色

| 用途 | 亮色模式 | 深色模式 |
| --- | --- | --- |
| 页面背景 | `#F5F6F8` | `#14171C` |
| 卡片 / 容器 | `#FFFFFF` | `#1B1F26` |
| 表头 / 次级底 | `#FAFBFC` | `#22272F` |
| 边框 | `#E3E6EB` | `#2B313B` |
| 分割线 | `#EDEFF2` | `#242A33` |
| 文字 主 / 次 / 弱 | `#1F2329` / `#5A6069` / `#8A9099` | `#E6E9EF` / `#A6ADB8` / `#767E8B` |
| Sider 底 | `#FFFFFF`（亮色改为浅色 Sider，见 §3.3） | `#14171C` |

> **深色模式不是可选项**：PRD US-9 定义夜间 23:00 批量任务，共享中心确实存在夜班与加班场景，必须支持。

### 2.4 字体

- 中文栈：`"PingFang SC", "Microsoft YaHei", "Hiragino Sans GB", sans-serif`
- 西文 / 数字界面：`Inter, system-ui, sans-serif`
- **等宽栈（硬要求）**：`"JetBrains Mono", Consolas, "SF Mono", monospace`

| 层级 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| 指标数 | 24px / 32px，weight 600 | 仪表盘 Statistic |
| 区块标题 | 16px / 24px，weight 600 | Modal / Drawer 标题 |
| 卡片标题 | 14px / 20px，weight 600 | Card 头（大小卡统一走 `headerFontSize` / `headerFontSizeSM`） |
| 小标题 | 14px / 22px，weight 600 | 分组名 |
| 正文 | 13px / 20px | 默认 |
| 表格 | 12px / 20px | 所有表格与列表 |
| 辅助 | 11px / 16px | 时间戳、提示、快捷键 |

**两个 Windows 上的坑（写死在本规范里，别再踩）**：

1. **雅黑只有 400 / 700 两档字面**：`font-weight: 500` 实际取 Regular，与 400 像素级一致（canvas 像素比对 0 差异）。要"加粗"就必须写 600 及以上才会命中 Bold 面；反过来 13px 白字压深色底用 Bold 会糊笔画，所以卡片标题用 14px + 600。
2. **文字必须落在整像素行上**：dpr=1 时元素顶边是小数（如 `.5`），一行中文被拆到两个物理像素行，观感就是"发虚 / 往下塌"。Card 头高度由 token 算出来是 40 / 36.8 这类小数，减去 1px 下边框再把 20.8 的行盒居中，标题正好落在 7.5px 上。做法是把 `(高度 − 边框 − 行高) / 2` 配成整数：`min-height: 39px`（小卡 37px）+ `line-height: 20px`。

**等宽字体强制场景**：金额、税号、发票号、订单号、trace id、token 数。
统一用 `<Mono>` 组件包裹，禁止散落手写 `fontFamily`（v1 已有此约定，v2 保留并扩大到"所有标识符"）。

### 2.5 间距 / 圆角 / 阴影 / 动效

| 类别 | 规范 |
| --- | --- |
| 间距 | 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32`；卡片间距 12px，页面 padding 16px |
| 圆角 | 控件 6px｜卡片 10px｜弹层 / Modal 12px｜Tag 4px |
| 阴影 | **卡片不用阴影**，靠 0.5px 边框分层（专业系统观感、减少噪点）；仅弹层 / 下拉用 `0 4px 16px rgba(16,24,40,.08)` |
| 动效 | 120ms（hover / 状态切换）、200ms（展开 / 抽屉）；缓动 `cubic-bezier(.4,0,.2,1)`；**全部尊重 `prefers-reduced-motion`** |

### 3.3 Sider 规范

- 宽度 **216px**（展开）/ **56px**（收起，仅图标）
- **亮色模式改为浅色 Sider**（`#FFFFFF` + 右侧 1px 分割线），取代 v1 的深色 `#001529`
  → 理由：深色 Sider 会把视线锚在左侧，而复核员 90% 时间该盯中间的内容区；浅色 Sider 让"内容"成为视觉重心
- 组标题：11px、字距 0.5px、弱色、上方 12px 间距
- 选中态：左侧 **3px 主色竖条** + 主色浅底 + 主色深字（**不用 v1 的蓝底白字**，太重）
- 徽标：复核工作台右侧显示待复核数量徽标（P0 数红、其余灰）

## 5. 核心屏：复核工作台 `/review`

> 全系统的设计重心。目标来自 PRD：单张操作 ≤ 3 次点击或快捷键完成，耗时 ≤ 1.5 分钟。

### 5.1 三栏结构

```
┌──────────┬──────────────────┬──────────────┐
│ ① 队列    │ ② 票据影像        │ ③ 对照与建议  │
│ 240px    │ 弹性（最小 480px） │ 360px        │
│ 可折叠    │ 可缩放 / 翻页     │ 可 Tab 切换   │
├──────────┴──────────────────┴──────────────┤
│ 决策条（常驻置底）：A 采纳 · S 驳回 · K 下一张   │
└─────────────────────────────────────────────┘
```

### 5.2 ① 队列（左）

- 按优先级 **P0 / P1 / P2 分组**，组内按时间升序
- 每项：发票号（等宽）+ 销方简称 + 金额（等宽）+ 归因 Tag
- 虚拟滚动（单批可能上百张）；顶部显示进度 `第 3 / 17 张`
- 选中态：主色浅底 + 左侧 3px 主色竖条
- **J / K** 上下切换，不碰鼠标

### 5.3 ② 票据影像（中）— 本版最大增强

- PDF 原件渲染（pdf.js），支持缩放、翻页、适应宽度
- **字段 ↔ 影像坐标联动**：选中字段表任一行 → 影像上对应区域出现主色高亮框
  → 数据来源：L1 版面解析已产出 `bbox` 坐标（PRD §6.2），v1 完全没用上，v2 必须接
- 影像右上角常驻：页数 / dpi / 来源（upload · scheduled）
- 无文本层的扫描件：显示"扫描件，已走多模态解析"提示条（PRD 常见坑：这不是 bug）

### 5.4 ③ 对照与建议（右）

两个 Tab：**字段对照** / **三单对照**

**字段对照表**

| 字段 | 抽取値 | 来源 | 置信度 |
| --- | --- | --- | --- |
| 价税合计 | ¥93,190.06 | llm:deepseek | 0.98 |
| 不含税金额 | ¥87,915.15 | llm:deepseek | 0.96 |
| 数量 | 5 | llm:deepseek | **0.62** ⚠ |

- 置信度用 **迷你条 + 数字**（不用裸数字）：`≥0.95` 隐藏条形、`0.9-0.95` 灰条、`<0.9` 琥珀条并整行浅琥珀底
- 来源列显示 `llm:{provider}:{model}` 或 `parser`，等宽小字 —— 这是"可审计"在字段级的落地
- 点击行 → 影像联动高亮

**三单对照表**（发票 / PO / GRN / 合同 四列并排）

| 维度 | 发票 | PO | GRN | 判定 |
| --- | --- | --- | --- | --- |
| 销方税号 | 9131…02P | 9131…02P | — | 一致 |
| 数量 | 5 | 5 | 3 | **不一致** QTY_MISMATCH |
| 金额 | 93,190.06 | 93,190.06 | — | 一致（容差内） |

- 差异 cell：红底 + 归因编码 Tag；**首个失败维度即停**（PRD §6.3），后续维度显示"—"并置灰，避免误导
- 一致 cell 保持中性，不加绿色（原则①：彩色只留给异常）

**AI 归因建议块**（青色虚线框）

- 文案：归因说明 + 建议动作 + 依据（规则 ID / 知识库文档引用）
- **只读**，不提供"采纳 AI 结论"的一键按钮；可提供的按钮是"填入驳回原因"这类辅助动作
- 无引用时显示"本建议无文档依据"并降级为灰色（PRD F15：无引用拒答）

### 5.5 决策条（置底常驻）

- 四按钮：`A 采纳`（主色实心）｜`S 驳回`（红色描边）｜`K 下一张`（中性）｜`E 编辑字段`（中性）
- 右侧常驻：本张耗时计时器 `00:42` + 目标 `≤ 1:30`（超时变琥珀）—— 用轻量压力感推动提效，也是 PRD 指标的可视化
- 驳回必须填原因（必填校验 + 常用原因快捷选择）

### 5.6 键盘体系

| 键 | 行为 |
| --- | --- |
| `J` / `K` | 上一张 / 下一张 |
| `A` | 采纳 |
| `S` | 驳回（打开原因弹窗） |
| `E` | 编辑当前聚焦字段 |
| `⌘K` / `Ctrl+K` | 命令面板（跳单据 / 切页面 / 切主题） |
| `?` | 快捷键速查面板 |
| `Esc` | 取消当前操作 |

规则：输入框聚焦时不触发；焦点已落在弹窗 / 抽屉 / 浮层内时，这次按键属于那个浮层，页面级快捷键不响应（否则驳回弹窗开着按 K 会切走底下的单据）；所有快捷键在页面右下角有可折叠的常驻提示条。

J/K 的"上一张 / 下一张"走**左侧队列的可见顺序**（先按 P0 / P1 / P2 分组，组内时间升序），而不是接口返回的数组顺序，"第 N / 共 M 张"用同一个顺序计数。

## 6. 其余七屏要点

### 6.1 扫描件池 `/documents`
- 工具条：搜索 + 状态 Segmented + 来源筛选 + **上传扫描件**（主色）
- 上传：`Upload.Dragger`，PDF ≤ 20MB / ≤ 50 页；超限行标红且禁止提交
- **支持拖放到表格区直接触发**（v1 已有，保留）
- 表格行：识别失败整行红；低置信整行琥珀
- 空态：引导文案 + 说明"今晚 23:00 定时任务将自动拉取"

### 6.2 规则配置 `/rules`
- 表单：金额容差 / 数量容差 / 日期窗口 / 低置信强制人工 / 税号不一致驳回
- **v2 增强：版本左右 diff 视图**——发布前对比"当前生效版 vs 待发布版"，差异项高亮
- 影响范围预览：影响 N 张在途单、M 张结果翻转
- 发布走二次确认；版本历史可回滚

### 6.3 知识库 `/kb`（新增）
- 文档列表：标题 / 类型（制度·SOP·税规·案例·版式）/ 版本 / 有效期 / 状态
- **过期文档灰显**并提示"有效期已过，不参与检索"（PRD §7.3 effective_to）
- 检索测试面板：输入问题 → 返回答案 + 命中的文档块引用（强制展示引用，无引用则拒答）
- 上传：解析 → 分块 → 向量化，显示分块数与状态

### 6.4 Key 管理 `/providers`
- provider 表：名称 / 模型 / 状态 / tokens / 成本 / 操作
- **Key 永不回显**，只显示 `sk-****abcd`（末 4 位）
- 成本归因到 provider + 步骤（对应 `ctrl.llm_usage`）

### 6.5 评测中心 `/evals`
- 指标卡：字段级准确率 / 整单通过率 / 自动通过率 / 平均延迟 / 成本
- 字段级准确率进度条列表，未达标字段标琥珀
- **发布门禁卡**：阻塞项未达标禁止发布，「仍要发布」需二次确认

### 6.6 仪表盘 `/dashboard`
- 4 指标卡：今日处理量 / 自动通过率（对比目标）/ 待复核积压（P0·P1·P2 分布）/ 本月 LLM 成本
- 趋势：堆叠柱状图（自动通过 主色 / 人工复核 琥珀 / 异常 红），14 天
- 归因分布：横向条形，按 PRD §6.4 的 8+ 类归因编码
- 新增：**今日待办**卡（我的队列还剩 N 张，直达工作台）

### 6.7 运行台账 `/traces`
- 左：筛选 + 列表（trace 短号 / 单据 / 步数 / 耗时 / 成本 / 状态）
- 右：垂直 Steps 链路（L0→L6），每步可展开看输入 / 输出摘要（等宽）
- **成本瀑布**：把每步 token 成本按步骤堆叠，直观看到"钱花在哪一步"
- L6 人工步骤显示等待时长

### 7.1 基于 antd v6 的 Token 定制

## 8. 交互与状态细则

| 场景 | 规则 |
| --- | --- |
| AI 建议 | 只读、青色虚线、无引用降级灰；**绝不提供一键执行** |
| 低置信字段 | 整行琥珀底 + `<ConfidenceBar>`，强制进人工队列 |
| 差异行 | 红色 cell + 归因 Tag；首个失败维度即停，后续置灰 |
| 金额 / 号码 | 一律等宽 + 千分位 + 两位小数 |
| 规则发布 | diff 预览 → 影响范围 → 二次确认 → 新版本号 |
| 评测门禁 | 阻塞项未达标禁止发布，强发需二次确认 |
| 驳回 | 必填原因（Modal + Textarea + 常用原因快选） |
| 加载 | 表格用 Skeleton 保持行高，禁止整页 Loading 导致布局跳动 |
| 空态 | Empty + 一句明确的下一步引导（如"今晚 23:00 自动处理"） |
| 错误 | 行内 Alert，保留数据不丢；失败可重试 |
| 消息提示 | 一律走 `@/utils/toast`（内部绑定 `App.useApp()` 的主题化实例）；antd 静态 `message.xxx()` 在 React 树外面拿不到 ThemeConfig，深色模式会弹白底黑字提示条 |
| 批量 | 选中后顶部出现批量操作条（批量采纳 / 批量驳回），并显示影响条数 |

## 9. 无障碍（WCAG AA 基线）

- **对比度**：正文 ≥ 4.5:1，大字 / 图形 ≥ 3:1。主色按钮白字 5.67:1 ✅
- **焦点可见**：所有可交互元素 2px 主色焦点环 + 2px offset，键盘 Tab 顺序 = 视觉顺序
- **不靠颜色单独传意**：差异除了红色，还必须有归因编码文字或图标（色盲可用）
- **屏幕阅读器**：表格用语义 `<table>`，Tag 带 `title`；队列切换用 `aria-live="polite"` 播报"第 N 张，共 M 张"
- **动效**：`prefers-reduced-motion: reduce` 时关闭全部过渡
- **触控**：可点击区域最小 32×32（桌面端作业系统，不适用 44px 移动端标准）

## 11. 设计决策备忘（面试可讲）

1. **人机双色系统**：用颜色把"AI 只做建议"这条架构原则固化进 UI，不用文案解释。
2. **差异优先的配色纪律**：中性底色，只有异常才上色 —— 彩色区域 = 注意力落点。
3. **浅色 Sider**：刻意把视线从导航移回内容区，因为复核员 90% 时间该看单据。
4. **字段 ↔ 影像 bbox 联动**：把 L1 已经产出但一直闲置的版面坐标用起来，这是"全链路设计"的证据。
5. **成本瀑布 + 耗时计时器**：把 PRD 的量化指标（≤1.5 分钟 / 成本可归因）变成界面上真实存在的反馈。
