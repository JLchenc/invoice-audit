## 步骤

1. **`pipeline/rules.py` 全部纯函数**，不 import 任何 DB/LLM：
   - `check_arith(fields, rules) -> list[Diff]`：价税合计 = 不含税 + 税额；税额 = Σ(明细金额×税率)；大写金额转数字后 = 价税合计；发票号码 8 位（纸质票）/ 20 位（数电票）格式；税率 ∈ 合法集
   - `cn_amount_to_decimal("叁万零玖拾陆元零叁分") -> Decimal("30096.03")`：零位规则按知识库 `fin-sop-field-extraction-spec-v1`——元位为零而分位非零时写「元零X分」。这个函数独立、可穷举测试
   - `match_three_way(fields, po, grn, contract, rules) -> list[Diff]`：按知识库 `fin-sop-three-way-match-v3` 的顺序——税号 → 金额（容差）→ 数量 → 日期窗口
   - `decide(arith_diffs, match_diffs, confidences, rules) -> (outcome, priority, diffs)`：pass / review / exception + 优先级 P0/P1/P2
   - 容差参数从 `rules` dict 传入（**不是常量**），保证和 `ctrl.rule_versions` 的 JSONB 同构
2. **「即停」语义按 SOP 实现**：**硬差异（hard）即停**——勾稽失败、判重命中、税号不一致、金额超容差，出现即停止后续比对；**提示级差异（warn）记录后继续**——容差内偏差、数量差、临界超窗。归因编码取首个失败维度（数据集里每张票最多一个编码，两种语义结果一致，但「warn 继续」能多给复核员信息）
3. **`tests/test_rules.py`**：每条规则至少 3 个用例（通过 / 临界 / 失败）；临界值必须覆盖（偏差恰好 0.5% 算内、0.51% 算外）
4. **`tests/test_samples.py` 用 50 份样本驱动自测**：读 `data/manifest.json`，把每份的 `ground_truth` 当输入、`simulated_field_confidence` 当字段置信度（PO/GRN/合同从 `data/*.json` fixture 取），断言输出 = manifest 的 `expected_outcome + reason_codes + review_priority`
5. **验收**：`uv run pytest` 全绿，且 50 份样本的规则判定与 ground truth **100% 一致**

### 为什么 P3 排在 LLM 前面（顺序是刻意的）

规则引擎是全链路**唯一不依赖任何外部服务、今天就能验收**的部分。它也是面试深挖「LLM 只做建议，规则和人做决定」时的底气：三单比对、容差计算、分流判定全是可单测的确定性代码。**规则绿了再碰 LLM。**

### 差异归因全集（数据集实际出现的 11 种）

| 归因编码 | level | outcome | priority | 触发条件 |
| --- | --- | --- | --- | --- |
| SUPPLIER_MISMATCH | hard | exception | **P0** | 发票销售方税号 ≠ PO 税号 |
| AMT_OVER_TOLERANCE | hard | exception | P1 | 价税合计差 > max(绝对容差, 金额×比例容差) |
| ARITH_FAIL | hard | exception | P1 | 勾稽任一硬规则失败（价税合计 / 税额 / 大写金额 / 号码格式） |
| TAX_RATE_INVALID | hard | exception | P1 | 税率不在合法集（样本集未出现，单测覆盖） |
| DUPLICATE_INVOICE | hard | exception | P1 | 发票号码已在池中（同票二次入池） |
| NO_PO | hard | exception | P1 | 无订单号 / 找不到对应 PO |
| NO_GRN | hard | exception | P2 | PO 存在但无入库单（货未到先开票） |
| DATE_OUT_OF_WINDOW（晚于合同截止日） | hard | exception | P2 | 超窗**且**开票日期 > 合同 date_to |
| DATE_OUT_OF_WINDOW（合同有效期内） | warn | review | P2 | 超窗但在合同期内（33 天临界超窗，提示级核实） |
| AMT_WITHIN_TOLERANCE | warn | review | P2 | 金额差在容差内（0 < 差 ≤ 允许值） |
| QTY_MISMATCH | warn | review | P2 | 入库数量 < 订单数量（多为部分入库） |
| FIELD_LOW_CONFIDENCE | warn | review | P2 | 关键字段置信度 < 0.9（红线：强制人工，与规则是否通过无关） |

> DATE_OUT_OF_WINDOW 的双结局是从样本数据反推出来的真实语义：`INV-2026-0004`（超窗 33 天、合同期内 → review P2）vs `INV-2026-0011`（超窗 59 天、晚于合同截止 2026-09-30 → exception P2）。manifest 的 `notes` 字段把这些边界写得很明白，调试时先读它。

## 常见坑（正文版，附录有展开）

- Decimal 比较用 `quantize(Decimal("0.01"))` 对齐精度再比，别直接 `==` float
- 「首个失败维度即停」的精确含义：**hard 即停、warn 记录后继续**（上文步骤 2）
- 关键字段低置信**永远**追加 FIELD_LOW_CONFIDENCE 并强制 review——即使三单全匹配（样本 `INV-2026-0002` 就是数据一致但税号置信 0.78 的例子）

### 前端类比一览

| 后端/领域概念 | 前端类比 |
| --- | --- |
| 纯函数 + dataclass | 一个不碰任何 I/O 的 utils 纯函数模块（同输入同输出，随便测） |
| `Diff` dataclass | `interface Diff { code; level; expected; actual; message }`——和前端 `MatchRow` 直接对齐 |
| `rules` dict 从外部传入 | 组件的 props / 配置对象，绝不写死在组件里——改容差不改代码 |
| pytest 参数化用例 | vitest 的 `it.each([...])` |
| `Decimal` | 金额计算的 `big.js` / 整数分：`0.1 + 0.2 !== 0.3` 的解药 |
| 50 样本回放测试 | 快照测试：拿固定 fixture 跑全量，diff 出回归 |
| `run_rule_chain` | 中间件/管道：L3 → 判重 → L4 → L5 依次穿过，每步可能短路 |

### Python 新人须知（P3 专用）

- **`@dataclass`**：自动生成 `__init__`/`__repr__` 的「记录类型」，等价 TS 的 `interface` + 构造函数。没有行为只有数据的东西都用它。
- **`Decimal(str(x))` 而不是 `Decimal(x)`**：`Decimal(0.1)` 会把 float 的二进制误差原样带进来（得到 0.1000000000000000055…），`Decimal("0.1")` 才是精确的 0.1。JSON 里来的数字先 `str()` 一遍。
- **`copy_abs()`**：Decimal 的绝对值，返回新对象不改原值（Decimal 全是不可变对象，类比 JS 的字符串）。
- **`min(iterable, key=...)`**：和 JS 的 `arr.reduce((a,b)=>f(a)<f(b)?a:b)` 一个意思；用 `key=order.index` 实现「P0 < P1 < P2 取最严重」。
- **测试不用起任何服务**：pytest 直接 import 纯函数跑，连数据库都不需要——这就是「先规则后 LLM」的第二个好处：测试秒级反馈。

### `server/app/pipeline/rules.py`

```python
"""
规则引擎（L3 勾稽 + L4 三单匹配 + L5 分流）：全部纯函数。

铁律：本文件不 import 任何 DB / LLM / FastAPI 模块。
输入输出全是普通 Python 数据结构，容差参数由调用方传入——
这保证了它能被 pytest 秒级验证，也保证了和 ctrl.rule_versions 的 JSONB 同构。

前端类比：一个零副作用的 utils/pure 模块，同输入永远同输出。
"""
from __future__ import annotations

import re
from dataclasses import asdict, dataclass
from datetime import date
from decimal import Decimal, ROUND_HALF_UP

# 两位小数的精度锚点：所有金额比较前都 quantize 到它，避免 0.01 级误差
TWO = Decimal("0.01")


@dataclass
class Diff:
    """一条差异。落库时 asdict() 进 match_results.diffs (JSONB)，
    字段名和前端 MatchRow 的 code / withinTolerance 一一对应。"""
    code: str            # 归因编码，如 AMT_OVER_TOLERANCE
    level: str           # 'hard'（即停/exception 倾向）| 'warn'（提示级/review）
    expected: str        # 期望值（展示用字符串）
    actual: str          # 实际值
    message: str         # 给复核员看的人话

    def to_dict(self) -> dict:
        return asdict(self)


# 归因编码 → 复核优先级（P0 最严重）。outcome 由 level 推导，不在这里写死。
PRIORITY: dict[str, str] = {
    "SUPPLIER_MISMATCH": "P0",
    "AMT_OVER_TOLERANCE": "P1",
    "ARITH_FAIL": "P1",
    "TAX_RATE_INVALID": "P1",
    "DUPLICATE_INVOICE": "P1",
    "NO_PO": "P1",
    "NO_GRN": "P2",
    "DATE_OUT_OF_WINDOW": "P2",
    "AMT_WITHIN_TOLERANCE": "P2",
    "QTY_MISMATCH": "P2",
    "FIELD_LOW_CONFIDENCE": "P2",
}

# 置信度低于阈值的字段名集合（PRD 红线：金额、税号、发票号、日期）
KEY_FIELDS = (
    "invoice_no", "seller_tax_no", "buyer_tax_no",
    "amount_ex_tax", "tax_amount", "total_amount", "invoice_date",
)

# 默认规则集：与 data/manifest.json 的 tolerances / rule_version v1.0.0 完全一致。
# 真实运行时从 ctrl.rule_versions（status='published'）读，这里只是兜底 + 测试默认值。
DEFAULT_RULES: dict = {
    "amount_tolerance_abs": Decimal("0.01"),   # 绝对容差：0.01 元（对齐「分」）
    "amount_tolerance_pct": Decimal("0.005"),  # 比例容差：0.5%
    "qty_tolerance": 0,                        # 数量容差：0 件（差 1 件就算差异）
    "date_window_days": 30,                    # 开票日期距订单日 ≤ 30 天
    "low_confidence_threshold": Decimal("0.9"),
    "tax_rate_legal_set": [Decimal("0.13"), Decimal("0.09"), Decimal("0.06"),
                           Decimal("0.05"), Decimal("0.03"), Decimal("0.01"), Decimal("0")],
}


def d(x) -> Decimal:
    """万物转 Decimal（Decimal 原样过，其余走 str，避开 float 二进制误差）。"""
    return x if isinstance(x, Decimal) else Decimal(str(x))


# ---------------------------------------------------------------- 大写金额

CN_DIGITS = {"零": 0, "壹": 1, "贰": 2, "叁": 3, "肆": 4,
             "伍": 5, "陆": 6, "柒": 7, "捌": 8, "玖": 9}
CN_UNITS = {"拾": 10, "佰": 100, "仟": 1000}


def cn_amount_to_decimal(text: str) -> Decimal:
    """中文大写金额 → Decimal。

    规则来源：知识库 fin-sop-field-extraction-spec-v1（元位为零而分位非零写「元零X分」）。
    算法：元前逐字符累计（数字记 num、单位乘进 value、万一次性放大），
    元后只处理 角/分/整 三个字。

    ⚠️ 局限：不支持「亿」级分段（样本集金额远小于 1 亿）。要支持亿级需要
    分段算法（亿/万各算一段再相加），留作练习——测试会告诉你什么时候必须做。
    """
    text = text.replace("人民币", "").strip()
    yuan_part, _, tail = text.partition("元")

    value, num = 0, 0
    for ch in yuan_part:
        if ch in CN_DIGITS:
            num = CN_DIGITS[ch]                # 先记数字，等下一个单位来乘
        elif ch in CN_UNITS:
            value += (num or 1) * CN_UNITS[ch]  # 「壹拾」=1×10；「拾万」的拾前面没数字→按 1 算
            num = 0
        elif ch == "万":
            value = (value + num) * 10000       # 万是「把已有累计整体放大」
            num = 0
    value += num                                # 尾缀裸数字（如「伍元」的伍走不到单位分支）

    jiao, fen, pending = 0, 0, None
    for ch in tail:
        if ch in CN_DIGITS:
            pending = CN_DIGITS[ch]             # 「零叁分」：零先占位，叁覆盖 → 分=3、角=0
        elif ch == "角":
            jiao = pending or 0
            pending = None
        elif ch == "分":
            fen = pending or 0
            pending = None
        elif ch in ("整", "正"):
            break
    return (Decimal(value) + Decimal(jiao) / 10 + Decimal(fen) / 100).quantize(TWO)


# ---------------------------------------------------------------- L3 勾稽

def check_arith(fields: dict, rules: dict) -> list[Diff]:
    """发票内部算术自洽校验（确定性规则，不用 LLM）。命中即 hard。"""
    diffs: list[Diff] = []
    ex, tax, total = d(fields["amount_ex_tax"]), d(fields["tax_amount"]), d(fields["total_amount"])
    items = fields.get("items") or []

    # ① 价税合计 = 不含税 + 税额
    if (ex + tax).quantize(TWO) != total.quantize(TWO):
        diffs.append(Diff("ARITH_FAIL", "hard",
                          str((ex + tax).quantize(TWO)), str(total.quantize(TWO)),
                          "价税合计 ≠ 不含税金额 + 税额"))

    # ② 税额 = Σ(明细金额 × 税率)（四舍五入到分；parser 抽不到明细时 items 为空，跳过）
    if items:
        exp_tax = sum((d(it["amount"]) * d(it["tax_rate"])).quantize(TWO, ROUND_HALF_UP)
                      for it in items)
        if exp_tax != tax.quantize(TWO):
            diffs.append(Diff("ARITH_FAIL", "hard",
                              str(exp_tax), str(tax.quantize(TWO)),
                              "税额 ≠ Σ(明细金额×税率)"))

    # ③ 大写金额折算 = 价税合计（「叁万零玖拾陆元零叁分」→ 30096.03）
    cn = fields.get("total_amount_cn")
    if cn and cn_amount_to_decimal(cn) != total.quantize(TWO):
        diffs.append(Diff("ARITH_FAIL", "hard", cn, str(total.quantize(TWO)),
                          "大写金额折算 ≠ 价税合计"))

    # ④ 发票号码格式：8 位（纸质票）或 20 位（数电票）纯数字
    no = str(fields.get("invoice_no") or "")
    if not re.fullmatch(r"\d{8}|\d{20}", no):
        diffs.append(Diff("ARITH_FAIL", "hard", "8位或20位数字", no, "发票号码格式非法"))

    # ⑤ 税率 ∈ 合法集（13/9/6/5/3/1/0，高新免税等特殊票会被拦下转人工核实）
    legal = {d(r) for r in rules.get("tax_rate_legal_set", [])}
    for it in items:
        if d(it["tax_rate"]) not in legal:
            diffs.append(Diff("TAX_RATE_INVALID", "hard",
                              str(sorted(str(x) for x in legal)), str(it["tax_rate"]),
                              "税率不在合法集"))
    return diffs


def check_duplicate(invoice_no: str, seen: set[str]) -> Diff | None:
    """同票二次入池拦截。seen 由调用方维护（测试里是 set，P4 真实链路里是
    一条「查 invoice_fields 表里已有的发票号」的 SQL）。"""
    if invoice_no in seen:
        return Diff("DUPLICATE_INVOICE", "hard", invoice_no, invoice_no,
                    "重复发票：该发票号码已入池")
    return None


# ---------------------------------------------------------------- L4 三单匹配

def _as_date(x) -> date:
    return x if isinstance(x, date) else date.fromisoformat(str(x))


def match_three_way(fields: dict, po: dict | None, grn: dict | None,
                    contract: dict | None, rules: dict) -> list[Diff]:
    """按 SOP 顺序：税号 → 金额 → 数量 → 日期。hard 即停（return），warn 记录后继续。"""
    if po is None:
        return [Diff("NO_PO", "hard", "-", "-", "发票未注明订单号或找不到匹配 PO")]

    diffs: list[Diff] = []

    # ① 供应商税号（不一致即停，最高优先级 P0）
    if fields.get("seller_tax_no") != po["seller_tax_no"]:
        return [Diff("SUPPLIER_MISMATCH", "hard", po["seller_tax_no"],
                     fields.get("seller_tax_no") or "", "供应商税号与 PO 不一致")]

    # ② 金额（容差）——allowed = max(绝对容差, PO 金额 × 比例容差)，小票吃绝对值、大票吃比例
    inv_total = d(fields["total_amount"]).quantize(TWO)
    po_total = (d(po["amount_ex_tax"]) + d(po["tax_amount"])).quantize(TWO)
    gap = (inv_total - po_total).copy_abs()
    allowed = max(d(rules.get("amount_tolerance_abs", "0.01")),
                  (po_total * d(rules.get("amount_tolerance_pct", "0.005"))).quantize(TWO))
    if gap > allowed:                       # 恰好等于 allowed 算容差内（开区间才叫「超」）
        return [Diff("AMT_OVER_TOLERANCE", "hard", str(po_total), str(inv_total),
                     f"价税合计差 {gap}，超容差 {allowed}")]
    if gap > 0:                             # 0 < gap ≤ allowed：提示级，复核员确认即可
        diffs.append(Diff("AMT_WITHIN_TOLERANCE", "warn", str(po_total), str(inv_total),
                          f"价税合计差 {gap}，在容差 {allowed} 内"))

    # ③ 数量（PO 订单量 vs GRN 入库量；发票自身数量不参与——它可能按订单全量开）
    if grn is None:
        return diffs + [Diff("NO_GRN", "hard", "-", "-", "该 PO 无入库单")]
    recv = grn.get("received_qty") or {}
    for it in po.get("items", []):
        po_q, grn_q = it.get("qty", 0), recv.get(it["name"], 0)
        if po_q - grn_q > rules.get("qty_tolerance", 0):
            diffs.append(Diff("QTY_MISMATCH", "warn", f"{it['name']}×{po_q}",
                              f"{it['name']}×{grn_q}",
                              f"{it['name']} 入库 {grn_q} 少于订单 {po_q}"))

    # ④ 日期窗口（双结局：合同期内 → warn/review；晚于合同截止 → hard/exception）
    inv_date, order_date = _as_date(fields["invoice_date"]), _as_date(po["order_date"])
    window = rules.get("date_window_days", 30)
    late = (inv_date - order_date).days
    if late > window:
        level = "warn"
        if contract and inv_date > _as_date(contract["date_to"]):
            level = "hard"                  # 超窗还开在合同期外 → 严重
        diffs.append(Diff("DATE_OUT_OF_WINDOW", level, f"≤{window}天", f"{late}天",
                          f"开票日期距订单 {late} 天，超 {window} 天窗口"))
    return diffs


# ---------------------------------------------------------------- L5 分流

def decide(arith_diffs: list[Diff], match_diffs: list[Diff],
           confidences: dict | None, rules: dict) -> tuple[str, str | None, list[Diff]]:
    """终态判定：outcome = exception|review|pass；priority = P0|P1|P2。

    红线②：关键字段低置信强制人工——即使三单全匹配也拦下（宁可多审，不可错放）。
    """
    diffs = [*arith_diffs, *match_diffs]
    thr = d(rules.get("low_confidence_threshold", "0.9"))
    low = [k for k in KEY_FIELDS
           if confidences and k in confidences and d(confidences[k]) < thr]
    if low:
        diffs.append(Diff("FIELD_LOW_CONFIDENCE", "warn", f"≥{thr}", ",".join(low),
                          "关键字段低置信：" + ",".join(low)))

    if not diffs:
        return "pass", None, diffs
    outcome = "exception" if any(x.level == "hard" for x in diffs) else "review"
    order = ["P0", "P1", "P2"]                       # P0 最严重
    priority = min((PRIORITY[x.code] for x in diffs), key=order.index)
    return outcome, priority, diffs


# ---------------------------------------------------------------- 总入口（P4 复用）

def run_rule_chain(fields: dict, confidences: dict | None, po: dict | None, grn: dict | None,
                   contract: dict | None, seen: set[str], rules: dict
                   ) -> tuple[str, str | None, list[Diff]]:
    """L3 勾稽 → 判重 → L4 匹配 → L5 分流，一条链跑完。

    即停语义：勾稽 hard 失败或判重命中 → 跳过三单匹配（归因取首个失败维度）。
    P4 的 runner 直接调这个函数；本阶段的测试也调它。
    """
    arith = check_arith(fields, rules)
    no = str(fields.get("invoice_no") or "")
    dup = check_duplicate(no, seen)
    if dup is not None or any(x.level == "hard" for x in arith):
        match: list[Diff] = []
    else:
        match = match_three_way(fields, po, grn, contract, rules)
    if dup is not None:
        match = [dup, *match]
    outcome, priority, diffs = decide(arith, match, confidences, rules)
    if no:
        seen.add(no)
    return outcome, priority, diffs
```

```python
"""用 data/manifest.json 的 50 份样本做「快照式」回归：
ground_truth 当输入、simulated_field_confidence 当字段置信度，
断言 run_rule_chain 的输出与 manifest 期望完全一致。

import json
from decimal import Decimal
from pathlib import Path

from app.pipeline.rules import DEFAULT_RULES, run_rule_chain

# 本文件在 server/tests/ → parents[2] 是项目根（data/ 的父目录）
DATA = Path(__file__).resolve().parents[2] / "data"


def _load():
    man = json.loads((DATA / "manifest.json").read_text(encoding="utf-8"))
    pos = {r["po_number"]: r for r in json.loads((DATA / "purchase_orders.json").read_text(encoding="utf-8"))}

def _find_contract(contracts, seller_tax_no, order_date):
    """合同按 销售方税号 + 覆盖订单日期 匹配（ISO 字符串比较即日期比较）。"""
    for c in contracts:
        if c["seller_tax_no"] == seller_tax_no and c["date_from"] <= order_date <= c["date_to"]:
            return c
    return None


def test_50_samples_match_ground_truth():
    man, pos, grns, contracts = _load()

        po = pos.get(inv["po_number"]) if inv.get("po_number") else None
        grn = grns.get(inv["grn_number"]) if inv.get("grn_number") else None
        contract = _find_contract(contracts, po["seller_tax_no"], po["order_date"]) if po else None

        outcome, priority, diffs = run_rule_chain(fields, conf, po, grn, contract, seen, DEFAULT_RULES)
        codes = [x.code for x in diffs]

        assert codes == inv["reason_codes"], \
            f"{inv['file']} codes {codes} != {inv['reason_codes']}，notes：{inv.get('notes')}"
        checked += 1
    assert checked == 50
```

### P3 常见坑（踩之前先读）

- **❶ 勾稽 hard 失败后必须「即停」，不再跑三单匹配**。作者实测踩过：初版把 ARITH_FAIL 和三单匹配结果全并在一起，`INV-2026-0010`（勾稽差 120 元的票，其 PO 金额也被同步放大）会同时产出 `['ARITH_FAIL', 'AMT_OVER_TOLERANCE']`，而 manifest 只期望 `['ARITH_FAIL']`。**hard 即停**是 SOP 的原话，也是数据集的语义。
- **❷ 判重结果别忘了并进 decide 的入参**。作者同样实测踩过：`check_duplicate` 算出了 diff，却只把它当作「跳过三单匹配」的开关，没加进差异列表——5 张重复票全部误判 pass。判重是 hard 差异，必须出现在 codes 里。
- **容差开闭区间**：`gap > allowed` 判超——**恰好等于 allowed 算容差内**（样本 INV-2026-0005 差 0.37%、INV-2026-0007 差 0.42% 都在 0.5% 内，构造数据时就是按开区间算的）。
- **`Decimal(str(json_float))`**：JSON 里的 `107168.54` 是 float，直接 `Decimal(x)` 会带二进制尾巴；先 `str()`。比较前双方都 `quantize(TWO)`。
- **税率合法集别写死 `0.13/0.06`**：样本集恰好只有这两档，但合法集是规则（`tax_rate_legal_set`），从 rules 传入，单测里用 0.17 验证会拦。
- **`min(..., key=order.index)` 的 P0/P1/P2 排序**：不是字符串排序（"P0" < "P1" < "P2" 字典序恰好也对，但别依赖运气——用显式 order 列表）。
- **重复票判定依赖处理顺序**：测试按 manifest 文件顺序串行入池，重复票（0046~0050）排在原票（0003/0008/0009/0017/0022）之后才成立。P5 真实队列是多 worker 并发的，顺序不保证——那边的文档会讲怎么处理（演示期 `max_jobs=1` 最省事）。
