1. **models 用一个 MetaData，表声明带 schema**——Alembic autogenerate 才能一次认全：
   ```python
   # ⚠️ 下面两块是「关键思路示意」，不是让你把 base.py 删成只剩这一行！
   # base.py 早就在 P0 阶段写好【完整版】了（含 engine / SessionLocal / get_session，见 P0 附录），
   # 这里只高亮两个要点：① 全库只有一个 Base  ② schema 写在模型上，不在 base.py。

   # 要点①：base.py 里只有一个 Base 基类（你已写好的完整版，保持原样，别删 engine/session）
   class Base(DeclarativeBase): pass

   # 要点②：schema 是【每张模型表】自己声明的，不写在 base.py
   # models/app_models.py 里：
   class InvoiceDocument(Base): __tablename__="invoice_documents"; __table_args__={"schema":"app"}
   # models/ctrl_models.py 里：__table_args__={"schema":"ctrl"}
   ```
   > **保持一致提醒（重要）**：`base.py` 保持你 P0 写的完整版（`Base` + `engine` + `SessionLocal` + `get_session`），**不要**改成只有 `class Base: pass`。`schema="app"/"ctrl"` 加到 `app/models/` 的两个模型文件里，Alembic `env.py` 配 `include_schemas=True` 才能一次认全两套表。
2. **DDL 定稿如下（即 PRD §7.2 / §7.3 原文，原样搬进迁移脚本即可）**，`app` 7 张表 + `ctrl` 8 张表，一张不多一张不少。建模时 SQLAlchemy 类型对齐：BIGSERIAL→`BigInteger`+`Identity`、NUMERIC→`Numeric(asdecimal=True)`、JSONB→`JSONB`、TIMESTAMPTZ→`DateTime(timezone=True)`、`vector(1024)`→`Vector(1024)`（pgvector）。

   > 📌 **数据库小白必读（重要）**：下面这段 `CREATE TABLE ...` 的 SQL（叫 **DDL**），
   > **不是让你复制粘贴去 psql / 数据库客户端里执行的**！
   > - 它是什么：15 张表的「建表说明书」——描述每张表有哪些列、什么类型。相当于前端里的 `interface InvoiceDocument { id: number; fileName: string; ... }` 或表单字段定义，只是用 SQL 写出来。
   > - 它的作用：只是**对照目标**。你后面用 Python 写出的模型，跑完迁移后，库里真实生成的表必须和它一致（列名/类型对得上）。
   > - 正确做法（你真正要做的）：**写 Python 模型代码**（见本附录下方 `server/app/models/app_models.py` / `ctrl_models.py` 完整代码，已带注释）→ Alembic 自动比对差异生成迁移 → 迁移把表建进数据库。**你全程不手打一句 DDL。**
   > - 记不住就记这句：**DDL = 目标快照；Python 模型 = 你写的东西；Alembic = 把模型变成真实表的工具。**

- **schema 不会自动建**：迁移前先 `CREATE SCHEMA app; CREATE SCHEMA ctrl;`（或迁移脚本里带 `CREATE SCHEMA IF NOT EXISTS`）

### Python 新人须知（P1 专用）

- **schema 在 SQLAlchemy 怎么表达**：表不在默认 `public`，而在 `app` / `ctrl` 两个 schema。每张表类里加 `__table_args__ = {"schema": "app"}`（或 `"ctrl"`）。「一个表类 = 一张表」，类属性名 = 列名。
- **`Mapped` / `mapped_column` 是 SQLAlchemy 2.x 新写法**（2.0 风格），替代老式的 `Column("name", Type, ...)`。初学就照 `字段名 = mapped_column(类型, 约束...)` 写，类属性名即列名。
- **`Numeric` vs `float`**：钱必须用 `Numeric(14,2)` + `Numeric(asdecimal=True)` + Python `Decimal`。`float` 在二进制里无法精确表示小数（`0.1 + 0.2 ≠ 0.3`），财务算错就是事故。类比前端 `parseFloat` 算金额也有精度问题，所以金额要么用整数「分」要么用 decimal 库。**本项目全程不许用 float 碰钱。**
- **`server_default` vs `default`**：`default=...` 是 Python 侧生效（插入时 SQLAlchemy 帮你填）；`server_default=...` 是写进数据库 DDL 的列默认值（`DEFAULT now()` / `'[]'::jsonb`）。PRD 里的 `DEFAULT now()` 是**数据库侧**的，所以用 `server_default=func.now()` / `server_default=text("'[]'::jsonb")`，这样「建表后空表也有默认值」，和 DDL 完全对齐。
- **`JSONB`**：`from sqlalchemy.dialects.postgresql import JSONB`，跨 PostgreSQL 专属类型都要从 `dialects.postgresql` 导入。`TIMESTAMPTZ` 没有专门类型名，用 `DateTime(timezone=True)`。`TEXT[]` 数组用 `ARRAY(Text)`。`UUID` 用 `UUID as PG_UUID`。
- **`ForeignKey`**：外键写成 `mapped_column(BigInteger, ForeignKey("app.invoice_documents.id"))`，字符串 `"表名.列名"` 跨 schema 也能指。
- **pgvector 的 `Vector` 类型**：`kb_chunks.embedding vector(1024)` 不是标准 SQL 类型，用 `from pgvector.sqlalchemy import Vector`，`mapped_column(Vector(1024))`。**这个包刚才已经加进 `pyproject.toml` 并 `uv sync` 装好了（v0.5.1）**，否则 `import app.models` 直接 `ModuleNotFoundError`。

```python
from datetime import date, datetime

# SQLAlchemy 2.x 核心工具
from sqlalchemy import BigInteger, Date, DateTime, ForeignKey, Index, Integer, Numeric, String, Text, func, text
# JSONB 是 PostgreSQL 专属类型，要从 dialects.postgresql 导入

from sqlalchemy.orm import Mapped, mapped_column

# 全库唯一的 ORM 基类（在 app/db/base.py 里定义，所有表都继承它）
from app.db.base import Base

# 1) 扫描件池：每张上传/调度的发票扫描件一条记录
class InvoiceDocument(Base):
    __tablename__ = "invoice_documents"
    # 这张表属于 app schema（不是默认 public）
    __table_args__ = {"schema": "app"}
```

#### ① 用下面这份**完整版 `env.py` 整个覆盖**（不要只在模板上改几行）

> **为什么必须整份换**：Alembic 1.20 生成的模板用的是**同步** `engine_from_config`，
> 而你的 `DATABASE_URL` 是 `postgresql+asyncpg://`（异步驱动）。
> 同步 engine 拿到 asyncpg 会直接报 `InvalidRequestError: The asyncio extension requires an async driver`。
> 所以要把 online 模式改成「`create_async_engine` + `connection.run_sync(...)`」这一套。
> （下面这份是**实测跑通过**的：autogenerate 认全 15 张表、`upgrade head` 15 张表全部建成。）

```python
"""Alembic 运行环境：让 autogenerate 认全 app / ctrl 双 schema 的表。

前端类比：这个文件 ≈ 打包器（Vite）的配置文件 —— 告诉工具「去哪找源码（metadata）、
输出用什么规范（URL / dialect）」。它不参与业务，但配置错了整个迁移链就跑不起来。
"""
import asyncio
from logging.config import fileConfig

from alembic import context
from sqlalchemy import pool
from sqlalchemy.ext.asyncio import create_async_engine

# ① config 就是 alembic.ini 在 Python 里的对象视图（能读里面的配置项）
config = context.config

# ② 让 alembic.ini 里配的日志格式生效（控制台那些 INFO ... 就是这里挂上去的）
if config.config_file_name is not None:
    fileConfig(config.config_file_name)

# ③ 关键一步：把 15 张表「登记」进 Base.metadata，autogenerate 才看得见表。
#    import app.models 是「副作用导入」——只为触发 models/__init__.py 里对两个模型文件的 import，
#    执行过它，Base.metadata.tables 里才会出现那 15 张表。少了这行 → autogenerate 生成空迁移。
from app.core.config import get_settings  # noqa: E402
from app.db.base import Base  # noqa: E402
import app.models  # noqa: E402,F401

settings = get_settings()          # 连接串从 .env 读，绝不硬编码进 alembic.ini
target_metadata = Base.metadata    # autogenerate 的比对基准 = Python 模型这一侧

def run_migrations_offline() -> None:
    """离线模式：只生成 SQL 文本、不连库（`alembic upgrade head --sql` 用）。"""
    context.configure(
        url=settings.database_url,
        target_metadata=target_metadata,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
        include_schemas=True,      # ← 双 schema 必须
        compare_type=True,         # ← 列类型变化也纳入比对
    )
    with context.begin_transaction():
        context.run_migrations()

def do_run_migrations(connection) -> None:
    """真正跑迁移的逻辑，被 run_sync 包成同步调用塞进异步连接里。"""
    context.configure(
        connection=connection,
        target_metadata=target_metadata,
        include_schemas=True,          # ← 少了它：只认 public，app/ctrl 里的表被当成「已删除」
        compare_type=True,
        compare_server_default=True,   # ← 服务端默认值变化也纳入比对
    )
    with context.begin_transaction():
        context.run_migrations()

async def run_async_migrations() -> None:
    """异步入口：用 asyncpg 建连，再把同步的 do_run_migrations 交给 run_sync 执行。"""
    engine = create_async_engine(settings.database_url, poolclass=pool.NullPool)
    async with engine.connect() as connection:
        await connection.run_sync(do_run_migrations)   # ← 同步函数跑在异步连接上
    await engine.dispose()

def run_migrations_online() -> None:
    """命令行默认走这里。"""
    asyncio.run(run_async_migrations())

if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

> `alembic.ini` 里那行 `sqlalchemy.url = driver://user:pass@localhost/dbname` **不用改也不用删**，
> 因为上面的 `env.py` 完全不读它（URL 全来自 `settings`）。想更干净可以把它注释掉。

#### ② 给 `script.py.mako` 加一行 `import pgvector.sqlalchemy`（必做，否则迁移必炸）

Alembic 把 `Vector(1024)` 渲染成 `pgvector.sqlalchemy.vector.VECTOR(dim=1024)`（带模块路径），
但**不会自动加 import**，于是 `alembic upgrade head` 直接：


改 `app/db/migrations/script.py.mako`，在 `import sqlalchemy as sa` 下面加一行：

### 首个迁移 + schema 创建（重点：人工核对）

```powershell
cd D:\project\agent\invoice-audit\server
uv run alembic revision --autogenerate -m "init app+ctrl schemas"
```

**生成后必须人工核对 `versions/xxxx_init_app_ctrl_schemas.py` 的 `upgrade()`**，autogenerate 对下面几处经常出问题：

1. **schema 本身不会自动建**：Alembic 只在已存在的 schema 里建表，不会 `CREATE SCHEMA`。在 `upgrade()` **函数体内部**顶部手动加：
   ```python
   def upgrade() -> None:
       """Upgrade schema."""
       op.execute("CREATE SCHEMA IF NOT EXISTS app")
       op.execute("CREATE SCHEMA IF NOT EXISTS ctrl")
       # ... 下面是自动生成的 create_table ...
   ```
   > ⚠️ **前端同学最容易踩的一坑**：迁移文件是 `.py` 文件，里面每一行都得是 Python 代码。
   > 直接写 `CREATE SCHEMA IF NOT EXISTS app;` 会报 `SyntaxError: invalid syntax`。
   > 类比 JS：就像你在 `.js` 里裸写 `SELECT * FROM t` —— SQL 对 JS 引擎来说不是合法语句；
   > 在 Python 里同理，SQL 只能是**字符串**，交给 `op.execute("...")` 这个"执行器"去跑。
   > 另外注意缩进必须对齐（在 `def upgrade()` 里面），且**不能**写在 `def upgrade()` 之前。
   > `IF NOT EXISTS` 是幂等的：schema 已经被你手动建过也不会报错，所以这段可以放心留着（换新机器时它就是自动建 schema 的那一步）。
2. **`import pgvector.sqlalchemy` 有没有**：文件头如果只有 `import sqlalchemy as sa`，`upgrade()` 跑到 `kb_chunks` 那行必报 `NameError: name 'pgvector' is not defined`。补上即可（模板改过的话会自动带）。
3. **`kb_chunks.embedding` 维度**：确认类型是 `Vector(1024)`，不是丢失维度的 `Vector()`（维度丢了建不了 ivfflat 索引）。
4. **ivfflat 向量索引 autogenerate 会漏**：在 `upgrade()` 末尾手动补（或确认它生成了）：
   ```python
   op.execute(
       "CREATE INDEX IF NOT EXISTS idx_kb_chunks_embedding "
       "ON ctrl.kb_chunks USING ivfflat (embedding vector_cosine_ops) WITH (lists = 50)"
   )
   ```
   > ⚠️ 注意顺序：**表里没有数据时建 ivfflat 索引是允许的**，但建议等 P2 灌完 embedding 再建，效果更好。先不做也不影响 P1 验收。
5. **JSONB 的 `server_default`**：确认渲染成 `sa.text("'[]'::jsonb")` 这类，而不是被忽略。
6. **`VECTOR` 的模块前缀**：生成的写法是 `pgvector.sqlalchemy.vector.VECTOR(dim=1024)`（实测如此），不是 `Vector(1024)`——这是正常的，别手改，只要 import 在就行。

核对无误再执行：

```powershell
uv run alembic upgrade head
```

```python
Python 会把 `\\p`、`\\a` 当成转义序列，报 SyntaxWarning: invalid escape sequence。
想在 docstring 里写反斜杠，就把开头的三引号前面加个 r，变成原始字符串。
"""
import sys
from pathlib import Path

# ⚠️ 必须在 import app.* 之前执行：把 server/ 加进模块搜索路径。
#   直接跑 `python scripts/seed.py` 时，Python 把「脚本所在目录」scripts/ 放进 sys.path[0]，
#   server/ 并不在里面，于是 `from app.db.base import ...` 会报
#   ModuleNotFoundError: No module named 'app'。
#   这 6 行把它补回去。等价做法：`uv run python -m scripts.seed`（-m 会把当前目录加进 sys.path）。
SERVER_DIR = Path(__file__).resolve().parent.parent   # .../server/scripts -> .../server
if str(SERVER_DIR) not in sys.path:
    sys.path.insert(0, str(SERVER_DIR))

import asyncio  # noqa: E402
import json
from datetime import date
from decimal import Decimal

from sqlalchemy import Date, Numeric, select  # noqa: E402

from app.db.base import SessionLocal
from app.models.app_models import PurchaseOrder, GoodsReceipt, Contract
from app.models.ctrl_models import KbDocument, KbChunk

# 路径解析：本文件在 server/scripts/seed.py
#   .parent          = server/scripts
#   .parent.parent   = server
#   .parent.parent.parent = 项目根（server/ 和 data/ 的父目录）
ROOT = Path(__file__).resolve().parent.parent.parent
DATA = ROOT / "data"

def _convert(model, row: dict) -> dict:
    """把 JSON 里的一行「洗」成能直接塞进模型的 kwargs。

    干三件事：
      1. 过滤：丢掉模型没有的字段（PO 的 total_amount/buyer_name/seller_name、
         GRN 的 warehouse、contracts 的 seller_name、kb doc 的 keywords/chunks）
         —— 不过滤就会 TypeError: 'xxx' is an invalid keyword argument。
      2. 日期：JSON 里的日期是字符串 "2026-09-19"，必须转成 datetime.date。
         —— 不转就会（实测报错原文）：
            DBAPIError: invalid input for query argument $5: '2026-09-19'
            ('str' object has no attribute 'toordinal')
      3. 金额：float → Decimal（Numeric(14,2) 列）。float 有二进制精度误差（0.1+0.2≠0.3），
         财务金额一律用 Decimal(str(x))，别用 Decimal(float) 直接吞。
    """
    cols = {c.name: c for c in model.__table__.columns}
    out = {}
    for k, v in row.items():
        col = cols.get(k)
        if col is None or v is None:      # 模型没有这个字段 / 值为空 → 跳过
            continue
        t = col.type
        if isinstance(t, Date) and isinstance(v, str):
            out[k] = date.fromisoformat(v)          # "2026-09-19" -> date(2026, 9, 19)
        elif isinstance(t, Numeric) and isinstance(v, float):
            out[k] = Decimal(str(v))                # 87915.15 -> Decimal("87915.15")
        else:
            out[k] = v                              # 其余原样（str / list / dict 直接给 JSONB）
    return out

async def _seed_if_empty(session, model, rows, label):
    # 简单幂等：表已有数据就跳过，避免重复灌
    if (await session.execute(select(model))).scalars().first() is not None:
        print(f"skip {model.__tablename__} (已有数据)")
        return
    session.add_all([model(**_convert(model, row)) for row in rows])
    await session.commit()
    print(f"seeded {model.__tablename__}: {len(rows)} 行")

async def main():
    # 读 JSON（data/ 与 server/ 同级）
    po = json.loads((DATA / "purchase_orders.json").read_text(encoding="utf-8"))
    grn = json.loads((DATA / "goods_receipts.json").read_text(encoding="utf-8"))
    contracts = json.loads((DATA / "contracts.json").read_text(encoding="utf-8"))
    kb = json.loads((DATA / "kb_documents.json").read_text(encoding="utf-8"))

    async with SessionLocal() as session:
        # 三单主数据
        await _seed_if_empty(session, PurchaseOrder, po, "PO")
        await _seed_if_empty(session, GoodsReceipt, grn, "GRN")
        await _seed_if_empty(session, Contract, contracts, "Contract")

        # 知识库：documents + chunks（embedding 留空，P2 填向量）
        if (await session.execute(select(KbDocument))).scalars().first() is None:
            for doc in kb["documents"]:
                # 去掉 chunks 字段（不是 KbDocument 的列）、把 effective_from 转 date
                doc_row = _convert(KbDocument, doc)
                kb_doc = KbDocument(**doc_row)
                session.add(kb_doc)
                await session.flush()  # flush 拿到自增 id，才能给 chunks 当外键
                for i, chunk_text in enumerate(doc.get("chunks", [])):
                    session.add(KbChunk(
                        document_id=kb_doc.id,
                        chunk_index=i,
                        content=chunk_text,
                        embedding=None,        # ← P2 回填向量
                        chunk_metadata={},     # 属性叫 chunk_metadata，落到库里的列名仍是 metadata
                    ))
            await session.commit()
            print(f"seeded kb_documents: {len(kb['documents'])} 篇, "
                  f"kb_chunks: {sum(len(d.get('chunks', [])) for d in kb['documents'])} 块")
        else:
            print("skip kb_documents (已有数据)")

if __name__ == "__main__":
    # asyncio.run 启动异步主函数（uvicorn 之外跑脚本都这样）
    asyncio.run(main())
```

> 注：`kb_documents.json` 顶层是 `{kb_version, description, documents[], qa_cases[]}`——`qa_cases`（10 条制度问答评测用例）属于 W3 评测集，P1 不灌，留到评测中心再导入。

#### 灌库三个必须知道的点（都已实测）

1. **日期必须是 `date` 对象，不能是字符串**
   JSON 里的 `"2026-09-19"` 直接塞进 `DATE` 列会炸（实测原文）：
   ```
   DBAPIError: invalid input for query argument $5: '2026-09-19'
   ('str' object has no attribute 'toordinal')
   ```
   `_convert()` 里已经用 `date.fromisoformat()` 统一处理。

2. **灌库顺序：PO → GRN，不能颠倒**
   `app.goods_receipts.po_number` 有外键指向 `app.purchase_orders.po_number`（`app_models.py:75`）。
   先灌 GRN 会报：
   ```
   IntegrityError: insert or update on table "goods_receipts" violates foreign key
   constraint "goods_receipts_po_number_fkey"
   ```
   本文代码靠「每张表 `add_all` 后立刻 `commit`」天然保证了顺序——**别为了"省一次提交"把 PO 和 GRN 塞进同一次 `add_all`**，
   实测那样会失败（SQLAlchemy 的批量插入不会按外键自动排序）。

3. **`kb_chunks` 必须先 `flush()` 拿到 doc 的 id**
   `kb_chunks.document_id` 外键指向 `kb_documents.id`，而 id 是自增的。
   所以先 `session.add(kb_doc)` → `await session.flush()` 让数据库回填 id → 再插 chunks。
   （`flush` ≠ `commit`：flush 只把 SQL 发出去，事务还没提交。）

### P1 常见坑（踩之前先读）

- **`ModuleNotFoundError: No module named 'app'`**（跑 `python scripts/seed.py` 时）：`sys.path[0]` 是**脚本所在目录 `scripts/`**，不是 `server/`，所以找不到 `app` 包。两种解法：① 脚本顶部加 6 行 `SERVER_DIR = Path(__file__).resolve().parent.parent; sys.path.insert(0, str(SERVER_DIR))`（附录已含）；② 改用模块方式跑：`uv run python -m scripts.seed`（`-m` 会把当前目录加进 `sys.path`）。注意 `uv run uvicorn app.main:app` 不会有这个问题，因为 uvicorn 自己会把 cwd 加进去。
- **`ModuleNotFoundError: No module named 'pgvector'`**：忘了装。已加进 `pyproject.toml`，跑 `uv lock && uv sync` 即可。
- **`NameError: name 'pgvector' is not defined`**（在 `alembic upgrade head` 时报）：**这个项目必踩**。Alembic 把 `Vector(1024)` 渲染成 `pgvector.sqlalchemy.vector.VECTOR(dim=1024)`，但生成的文件头没有 `import pgvector`。改 `script.py.mako` 加一行 `import pgvector.sqlalchemy`（一次改好，以后所有迁移都自动带）；已经生成的那份则手动补 import。
- **`InvalidRequestError: The asyncio extension requires an async driver`**：`env.py` 还是模板原样（同步 `engine_from_config`），而 URL 是 `postgresql+asyncpg://`。用附录那份 `create_async_engine` + `run_sync` 的完整版覆盖。
- **`Can't locate revision identified by 'xxxx'`**：库里 `alembic_version` 表记着一个你本地 `versions/` 里不存在的版本号（多见于换机器、删过迁移文件、或复用别人的库）。清掉重来：`DROP TABLE public.alembic_version;` 再 `alembic upgrade head`。
- **autogenerate 不认双 schema**：`env.py` 漏了 `include_schemas=True` → 只生成 public 下的表或报空。三处 `context.configure` 都加上。
- **`CREATE SCHEMA` 不会自动生成**：首次迁移里手动 `op.execute("CREATE SCHEMA IF NOT EXISTS app/ctrl")`，否则建表报 `schema "app" does not exist`。
- **ivfflat 索引 + 维度**：autogenerate 可能漏索引或把 `Vector(1024)` 退化成 `Vector()`，手动补 `CREATE INDEX ... USING ivfflat ... WITH (lists=50)`。
- **fixture 多余字段**：`purchase_orders.json` 有 `total_amount`/`buyer_name`、`contracts.json` 有 `seller_name`、`kb_documents` 的 doc 有 `keywords` ——模型没有这些列，`model(**row)` 会 `TypeError`，用上面 `_rows_for` 按模型字段过滤。
- **`llm_usage.run_id` 不建外键到 `trace_records`**：trace 是高频写入，外键影响批量插入性能，代码层保证关联即可（PRD 也是这么定的）。
- **金额永不用 float**：`Numeric(14,2)` + Python `Decimal`；比较用 `quantize(Decimal("0.01"))` 对齐精度再比（P3 还会用到）。

#### 手搓期真实报错对照（已在你机器上实测复现）

| 你看到的报错 | 真正原因 | 改法 |
| --- | --- | --- |
| `ModuleNotFoundError: No module named 'date'` | `from date import data, datetime` —— 标准库模块是 `datetime`，且没有 `data` 这个东西 | `from datetime import date, datetime` |
| `ModuleNotFoundError: No module named 'salalchemy'` | 包名拼错（`salalchemy`），另外 `Mapped` / `mapped_column` 不在顶层包 | `from sqlalchemy import ...`；`from sqlalchemy.orm import Mapped, mapped_column` |
| `ConstraintColumnNotFoundError: Can't create Index on table 'x': no column named 'invoice_document_id' is present` | `Index("...", "invoice_document_id")` 里的**列名字符串**写错（本表列叫 `document_id`） | `Index("idx_fields_doc", "document_id")`（索引名也对齐 PRD 的 `idx_fields_doc`） |
| 建表成功但 **字段名和 PRD 对不上** | `upload_by` / `processd_at` 少字母 | `uploaded_by` / `processed_at`（seed、API、前端全都按 PRD 列名走，早改早省事） |
| `SAWarning: Attribute name 'metadata' should be left reserved for the MetaData instance` | `metadata` 是 Declarative 的**保留属性名**（Base 上那个 `MetaData`） | 属性改名、列名保留：`chunk_metadata = mapped_column("metadata", JSONB, nullable=False, server_default=text("'{}'::jsonb"))` —— 数据库里的列仍叫 `metadata`，与 PRD 一致 |
| `import app.models` 后 `len(Base.metadata.tables) == 0` | `app/models/__init__.py` 是空文件，两个模型模块**没被导入**，Alembic 扫不到 | 写 barrel：`from .app_models import *` + `from .ctrl_models import *`（清单第 3 步） |
| `SyntaxError: invalid syntax` 指向迁移文件里的 `CREATE SCHEMA` | 把**裸 SQL 直接写进 `.py` 文件**当语句用了。`.py` 里每一行都必须是 Python 代码，SQL 只是**字符串** | SQL 必须包成字符串、放进函数里：`op.execute("CREATE SCHEMA IF NOT EXISTS app")`（见下方说明） |

> **两个「看着像坑、其实不是」的写法（已实测，不用改）**：
> - `server_default="pending"`（裸字符串）：SQLAlchemy 会自动加引号，生成 `DEFAULT 'pending'`，**正确**。只有 `DEFAULT pending` 才会报错——那是手写 SQL 的情况。
> - `mapped_column(BigInteger, primary_key=True)` **不写 `Mapped[...]` 注解**：合法可用（类型显式给了就行），只是拿不到 IDE 的类型推断。想更规范可以补 `Mapped[int]`，但不是必须。
